# homeroom_api
Contract shared by the Next.js web app and the Flutter app. Every route is scoped to the
caller's school and role by Postgres row-level security (see backend/migrations); the
\"Roles\" line on each operation says who is meant to call it, and the database enforces it.

**Conventions**
- Auth: `Authorization: Bearer <jwt>`. The API maps the token to `people.id` and sets `app.person_id`.
- IDs are UUIDs. Dates are `YYYY-MM-DD`; timestamps are RFC 3339 UTC. Money is a decimal string in GHS minor-unit-safe form (`\"1850.00\"`), never a float.
- Lists are cursor-paginated: `?limit=50&cursor=...` returns `{ items, next_cursor }`.
- Errors use `application/problem+json`. A row the caller may not see is reported as **404**, not 403, so existence is not leaked. 403 is for a visible resource the caller may not change.
- Writes from the offline apps send an `Idempotency-Key` header; replays return the original result.
